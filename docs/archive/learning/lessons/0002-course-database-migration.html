Lesson 02 · Poodle backend · Five minutes

Make the course tables real

Your win: explain the startup warning, then bring the development database up to the course feature’s schema.

Why both messages are true

Poodle’s generated schema contains four course tables. The saved migration history does not contain them yet. “Latest database migration already applied” means the database has applied the latest saved revision.

1 · ModelA .spy.yaml file describes a table.
2 · MigrationSQL records the required database changes.
3 · DatabaseApplying that SQL creates the real tables.

Code generation prepares Dart classes and the target schema. A migration changes PostgreSQL. See Serverpod’s migration guide.

Try it in your running terminal

  1. Focus the terminal running serverpod start.
  2. Press lowercase m, without Shift. This creates and applies a migration.
  3. Wait for successful application. Look for a new directory under poodle_server/migrations/; its SQL should create the four tables below.
  4. In the default watch session, press lowercase r to restart. This reruns Poodle’s startup seed.
  5. Read the new startup output. The missing-table warning should disappear.
poodle_course
poodle_course_activity
poodle_course_membership
poodle_course_section

The keyboard actions are documented in Running your server. Press h for the session’s shortcuts if they differ.

If creation or application fails, keep the first error and send it to me. If it reports no model changes, send that output too. A repair migration reconciles the live database with a saved schema; first we need the missing course revision.

Recall before revealing
