1. Write the test before the screen

Put this in poodle_flutter/test/widget/splash_screen_test.dart. Leave the screen unchanged for now.

import 'package:flutter/material.dart';
import 'package:flutter_test/flutter_test.dart';
import 'package:poodle_flutter/screens/splash_screen.dart';

void main() {
  testWidgets('splash screen shows the Poodle name', (tester) async {
    await tester.pumpWidget(
      const MaterialApp(
        home: Scaffold(body: SplashScreen()),
      ),
    );

    expect(find.text('Poodle'), findsOneWidget);
  });
}

pumpWidget builds the screen; find.text looks for the label; findsOneWidget requires exactly one match. The app and scaffold supply the usual UI context. Flutter widget-testing guide.

Predict before running: Will the test pass? Which visible text does the current screen actually show?

From the project root, enter the Flutter package and run just this file:

cd poodle_flutter
rtk proxy flutter test test/widget/splash_screen_test.dart

Expected red: the assertion expects one match for “Poodle” and finds none. Read your actual output; the wording can vary. An import or SDK error is a setup problem to fix before proceeding.

Why test SplashScreen instead of MyApp?

MyApp already renders “Poodle” in MyHomePage's app bar. An unrestricted text search there could pass even though the splash body still shows the greeting form. Rendering the screen on its own makes this test sensitive to the behavior we agreed to build.

Reveal a minimal implementation after your attempt

Replace the splash file with:

import 'package:flutter/material.dart';

class SplashScreen extends StatelessWidget {
  const SplashScreen({super.key});

  @override
  Widget build(BuildContext context) {
    return const Center(child: Text('Poodle'));
  }

What this first win proves

It proves that the rendered splash widget contains the name. In your current app, MyHomePage uses that widget as its body. It does not yet establish a complete startup flow.

Your main() awaits initializeClient() before runApp(), so this Flutter widget cannot cover that earlier wait. The native launch screen handles the period before Flutter displays its first frame. Flutter's Android launch-screen documentation.
