Poodle / Quick reference

One behavior at a time.

Say what the user should see. Write the test. Observe the failure. Add enough code to pass.

The workflow

01 · RedRun one new test and explain its failure.
02 · GreenImplement the promised behavior and rerun.
03 · ReviewImprove structure if needed; keep tests passing.

Use one red → green cycle per behavior, then review. Do not force a refactor when the code is already clear. TDD process reference.

Read a failure before changing code

A missing expected label is a useful red result. An unresolved import, absent SDK, or broken test setup needs repair before it can tell you anything about the feature.
