# Identity access implementation results

Approved specification and plan: 2026-10-22. Source implementation is present;
the milestone is **not accepted complete** until database and runtime checks pass.

## Implemented

- Serverpod built-in email/password authentication and JWT sessions, with a
  consistent `poodle` issuer. Application code delegates hashing, proof validation,
  token refresh and rotation to the SDK.
- Persistent account access and single-use seven-day teacher-candidate invitations.
  Registration rechecks and consumes an invitation in the SDK account-creation
  transaction, with per-email advisory locking. Invitation purpose is persisted.
- Protected `account.me` and admin invitation list/create/revoke endpoints. Guards
  check current user/block state, account access, refresh-session validity and
  persisted admin authority. Issuers come from authenticated server identity.
- Password-reset completion revokes all sessions. Development logs verification
  codes; tests use captured delivery. Staging/production require a delivery adapter.
- Idempotent development-only admin bootstrap; explicit opt-in for test fixtures.
  Approved credentials are configured only in ignored local development secrets.
  Existing accounts are not promoted; changed passwords/removed admin authority
  are not restored. Account creation awaits migration and restart.
- Flutter live composition behind `AuthRepository`, SDK session management,
  protected account validation, startup recovery, immediate local logout, and
  an explicit retry when remote revocation or credential deletion fails.
- Secure remembered credentials or memory-only credentials, with durable deletion
  before switching policies and generation leases to prevent stale writes.
- English/Ukrainian invitation and password-reset forms, trusted account display,
  and admin invitation management. Live Google is hidden; fake authentication
  remains available through `main_preview.dart`. Onboarding and fixture dashboard
  behavior are preserved. Preview routes cannot enter live account/admin screens.

Global admin and course-scoped teacher/student remain the only roles.
`teacherApproved` is eligibility for future course membership, not a global role.
Course membership/content endpoints remain separate capability-map modules.
